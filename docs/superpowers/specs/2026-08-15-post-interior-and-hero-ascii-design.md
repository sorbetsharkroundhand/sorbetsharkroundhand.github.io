# Post Interior and Supplied Hero ASCII Design

## Status and scope

This supplement extends the approved ASCII Brutalism learning-notes design for issue #2. It addresses two follow-up requirements:

1. Redesign the inside of each post, not only the route header and surrounding chrome.
2. Replace the home hero illustration with the user-supplied ASCII composition.

The post Markdown, route slugs, visualization registration, static output, and accessibility behavior remain unchanged.

## Design read

This is an editorial learning-note redesign for people studying mathematics and machine learning. The visual language remains native-CSS ASCII Brutalism with `DESIGN_VARIANCE 8`, `MOTION_INTENSITY 3`, and `VISUAL_DENSITY 6`.

## Post interior

### Reading shell

The article body becomes a two-column reading shell:

- A narrow left rail provides `ON THIS NOTE`, the post's real level-two headings, and a compact reading-status label.
- The right column contains the readable prose at approximately 68-72 characters.
- Interactive figures continue to break out into the wide instrument area.

The rail is navigation, not decoration. Every item links to the heading ID generated by Astro. It uses the same order as the Markdown source. On viewports below 768px, it becomes a compact top index before the prose instead of remaining sticky or consuming horizontal space.

### Section rhythm

Level-two sections receive a visible zero-padded sequence marker generated by CSS counters. Headings, prose, formulas, code, and figures use distinct but related ruled zones:

- body copy remains sans-serif and high-contrast
- formulas occupy a quiet monochrome calculation band
- code uses the same sharp instrument-panel language as interactive scenes
- blockquotes become explicit notebook observations
- visualization slots align with the article shell and retain their scene-specific single accent

The educational text is not rewritten. Existing heading IDs, KaTeX output, inline code, code blocks, and visualization insertion headings remain stable.

### Metadata and navigation

The existing slug-specific ASCII header, publication date, topic links, archive link, and older/newer pager remain. The post title and introductory metadata lead into the new reading shell so the route reads as one continuous notebook rather than a generic article beneath a designed header.

## Supplied home ASCII

The attached 123-line text is the authoritative home hero art.

- Remove only fully blank outer lines.
- Preserve every non-empty line's character order and internal spacing.
- Trim uniform leading indentation only when it is shared by every non-empty line.
- Store the result in the ASCII design registry, not in page markup or Markdown content.
- Provide an accessible Korean description through the existing `AsciiArt` component.
- Render the same composition at desktop and mobile. Responsive CSS scales the monospace glyph size; it does not substitute a different drawing.

Because the supplied work is approximately 100 columns wide, the registry supports an explicit wider desktop contract for this entry while retaining existing limits for normal post, category, loading, and thumbnail art.

## Data flow

1. `src/pages/posts/[...slug].astro` renders the Markdown entry and receives Astro's heading metadata.
2. The page passes level-two headings to `PostLayout` with the post and neighbors.
3. `PostLayout` renders the heading-linked article index next to the slot containing static Markdown HTML.
4. The visualization integration continues inserting registered static figure slots after exact headings.
5. The ASCII registry resolves the supplied site hero for `kind: 'hero'`.

## Accessibility and responsive behavior

- The article index is a named navigation landmark.
- Heading links use real fragment URLs and visible keyboard focus.
- The supplied ASCII remains `aria-hidden`; its readable label describes the composition.
- The reading order remains header, article index, prose, pager.
- Mobile has no horizontal page overflow at 390px.
- Reduced-motion behavior and visualization cleanup are unchanged.
